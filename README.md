的团队都遇到过这种事：辛苦开发几个月的系统，客户拿到源码后转手挂到第二个域名上继续用，你连谁在盗用都不知道。更隐蔽的情况是，客户把源码交给第三方二开，二开的人顺手把授权校验代码删了，你的授权体系形同虚设。

这套PHP域名授权验证系统开源版，解决的就是这个问题。它的定位不是卖授权系统，而是给开发者一套可以自建、自控的授权校验中台——你的代码里嵌入几行验证逻辑，每次运行前向你的授权服务器发一个请求，服务器判断这个域名有没有被授权、授权有没有过期，返回结果决定功能是否可用。

核心机制：远程校验，签名防伪

最原始的域名授权是硬编码：<img width="2080" height="1024" alt="图片加水印 (2)" src="https://github.com/user-attachments/assets/26b0d9db-cbec-4831-ba0f-cc832248cd0d" />
在代码里写死域名判断，不符合就终止运行。这种方式改起来麻烦，客户拿到源码后直接删掉这段代码就绕过了。

这套系统的做法是远程授权验证。开发者在自己的服务器上部署授权系统作为授权服务器，然后在需要保护的PHP程序里嵌入客户端验证代码。校验逻辑不是简单的域名匹配，而是带签名的双向验证：客户端发送域名和签名，服务端验证签名合法性后，返回一个包含域名、过期时间等信息的token，客户端再用HMAC验证token未被篡改。密钥存在客户端代码里，但客户端无法伪造服务端的返回结果，签名校验不通过就直接拒绝。

授权管理：卡密、代理与盗版追踪

卡密授权是最实用的设计。你可以批量生成<img width="2080" height="1024" alt="图片加水印 (3)" src="https://github.com/user-attachments/assets/4cf080ab-b79b-4f69-8f4c-be00ff2e211e" />
授权卡密，代理拿卡密去卖，用户自助兑换后绑定自己的域名。系统支持代理功能、独立代理后台，代理可以无限生成卡密，后台自动记录谁生成的、谁兑换的。这意味着你可以发展分销渠道，让代理去卖授权，把授权分发变成一门可规模化的生意。

盗版追踪是事后追责的基础。系统会记录未授权域名的访问请求，在后台自动生成域名访问记录。虽然不能阻止盗用，但至少让你知道谁在盗用，为后续维权留下证据。

部署门槛与安全边界

HP 7.0以上、MySQL 5.6以上、Nginx或Apache即可运行。部署流程是标准的PHP程序安装流程——上传源码、导入数据库、修改数据库连接文件、访问后台。

但有几个安全细节需要留意。源码标注有一个文件有加密，其他开源，不影响二开，这个加密文件大概率是核心的签名校验逻辑，防止客户直接读取密钥生成规则。另外，授权服务器本身的域名和密钥必须保密，密钥如果泄露，攻击者可以伪造任意域名的授权返回。

小结

对于做源码分发生意的团队，这套PHP域名授权验证系统的价值在于，用几十行客户端代码，把谁在用我的代码、用到什么时候这件事从不可知变成可控。卡密体系支持渠道分销，盗版追踪提供事后追责依据，远程校验让硬编码绕过变得困难。

它不完美——服务端如果挂了，所有客户端都会验证失败；密钥泄露就意味着授权体系崩溃。但在零成本自建授权中台这个定位下，它提供了一个足够实用的起点。
